PART 1: CLIENT UNIT TESTS (RUST & PYTHON)
-------------------------------------------------------------------------------

TEST: Issue and Verify Token (Happy Path)
  Setup: Server running at 127.0.0.1:5111.
  Action:
    1. Issue Token16 for User1.
    2. Call verify_token(Token16).
  Assert:
    - Issued token is 16 bytes.
    - verify_token returns VerificationResult::Valid(User1).

TEST: Connect wasn't called.
  Action:
    1. Call verify_token on unconnected client
  Assert:
    - verify_token returns VerificationResult::Invalid.

TEST: Verify Invalid or Non-Existent Token
  Setup: Server running at 127.0.0.1:5111.
  Action:
    1. Generate random 16-byte token not issued on server.
    2. Call verify_token(random_token).
  Assert:
    - verify_token returns VerificationResult::Invalid.

TEST: Server Token TTL Client Expiration
  Setup: Server running at 127.0.0.1:5111.
  Action:
    1. Issue Token16 for User1 (configured server default TTL = 1s).
    2. Sleep 2 seconds.
    3. Call verify_token(Token16).
  Assert:
    - verify_token returns VerificationResult::Invalid.

TEST: Server Token TTL Server Expiration
  Setup: Server running at 127.0.0.1:5111.
  Action:
    1. Issue Token16 for User1 (configured server default TTL = 1s).
    2. Close client.
    3. Wait for 2 seconds.
    4. Start new client.
    5. Call verify_token(Token16).
  Assert:
    - verify_token returns VerificationResult::Invalid.

TEST: Local In-Memory Cache Hit
  Setup: Server at 127.0.0.1:5111. Client configured with local_cache_ttl = 60 seconds.
  Action:
    1. Issue Token16 for User1.
    2. Call verify_token(Token16) -> populates local cache.
    3. Stop server process.
    4. Call verify_token(Token16) again.
  Assert:
    - Second verify_token returns VerificationResult::ValidDegraded(User1) without network call.

TEST: Explicit Token Revocation (Single Node)
  Setup: Server running at 127.0.0.1:5111.
  Action:
    1. Issue Token16 for User1.
    2. Call verify_token(Token16) -> populates local cache.
    3. Call revoke_token(Token16).
    4. Call verify_token(Token16).
  Assert:
    - revoke_token succeeds.
    - Local cache drops Token16.
    - Subsequent verify_token returns VerificationResult::Invalid.

TEST: Token32 Payload Variant
  Setup: Server running at 127.0.0.1:5111.
  Action:
    1. Issue Token32 for User1.
    2. Call verify_token(Token32).
  Assert:
    - Issued token is 32 bytes.
    - verify_token returns VerificationResult::Valid(User1).

TEST: Stream Outage & Safety TTL Eviction
  Setup: Server running at 127.0.0.1:5111. Client configured with local_cache_ttl = 1 second.
  Action:
    1. Issue Token16 and call verify_token(Token16) -> populates local cache.
    2. Disconnect gRPC stream / simulate network outage.
    3. Wait 2 seconds (local_cache_ttl safety window expires).
    4. Call verify_token(Token16).
  Assert:
    - Local cache entry expires naturally after 2 seconds.
    - Re-verification attempt fails and throws/returns TokenServiceError::ServiceDisconnected.

TEST: Independent Token Revocation
  Setup: Server running at 127.0.0.1:5111.
  Action:
    1. Issue Token16 (T1) and Token16 (T2) for the same User1.
    2. Call verify_token(T1) and verify_token(T2) -> both cached.
    3. Call revoke_token(T1).
    4. Call verify_token(T1) and verify_token(T2).
  Assert:
    - T1 verification (step 4) returns VerificationResult::Invalid.
    - T2 verification (step 4) returns VerificationResult::Valid(User1).

TEST: Client gRPC Stream Auto-Reconnect
  Setup: Server running at 127.0.0.1:5111. Client with backoff max_delay = 500ms.
  Action:
    1. Client connects and starts SubscribeRevocations stream.
    2. Temporarily stop/restart server process to break stream.
    3. Wait 1 second for client exponential backoff reconnect loop to establish new stream.
    4. Issue and revoke Token16 on restarted server.
  Assert:
    - Client automatically re-establishes gRPC stream without throwing error.
    - Client receives revocation event over re-established stream.

TEST: Cached Tokens Do Not Outlive Server-Side Tokens
  Setup: Server running at 127.0.0.1:5111 (server default TTL = 3 seconds). Client configured with local_cache_ttl = 60 seconds.
  Action:
    1. Issue Token16 for User1.
    2. Sleep for 2 seconds.
    3. Close client.
    4. Start new client.
    5. Call verify_token(Token16) -> hits server, caches locally with remaining server TTL = 1s.
    6. Sleep for 2 seconds.
    7. Call verify_token(Token16) -> reads local cache.
  Assert:
    - First verify_token (step 5) returns VerificationResult::Valid(User1).
    - Second verify_token (step 7) returns VerificationResult::Invalid (cache evicted via remaining server TTL bound).

TEST: Uncached Verify Miss Fails on Service Disconnect
  Setup: Client connected to 127.0.0.1:5111.
  Action:
    1. Stop gRPC server process.
    2. Call verify_token(uncached_token).

TEST: Issue Token Fails on Service Disconnect

PART 2: MULTI-REPLICA INTEGRATION TESTS (RUST)
-------------------------------------------------------------------------------

TEST: Cross-Replica Read (Shared Redis Storage)
  Setup:
    - Shared Redis running at 127.0.0.1:6379.
    - Replica A at 127.0.0.1:5111, Replica B at 127.0.0.1:5112.
    - Client A connected to Replica A; Client B connected to Replica B.
  Action:
    1. Client A calls issue_token(User1) on Replica A -> gets Token16.
    2. Client B calls verify_token(Token16) on Replica B.
  Assert:
    - Client B verify_token returns VerificationResult::Valid(User1).

TEST: Cross-Replica Revocation Push (Redis Pub/Sub)
  Setup:
    - Shared Redis running at 127.0.0.1:6379.
    - Replica A at 127.0.0.1:5111, Replica B at 127.0.0.1:5112.
    - Client A connected to Replica A; Client B connected to Replica B.
  Action:
    1. Client A calls issue_token(User1) on Replica A -> gets Token16.
    2. Client B calls verify_token(Token16) on Replica B -> populates Client B local cache.
    3. Client A calls revoke_token(Token16) on Replica A.
    4. Wait up to 1s for redis pub/sub and gRPC revocation stream push to Client B.
    5. Client B calls verify_token(Token16).
  Assert:
    - Client B's local cache is dropped via gRPC stream push.
    - Client B verify_token returns VerificationResult::Invalid.

TEST: Multi-Client Revocation Broadcast
  Setup:
    - Shared Redis at 127.0.0.1:6379.
    - Replica A at 127.0.0.1:5111, Replica B at 127.0.0.1:5112, Replica C at 127.0.0.1:5113.
    - Client A on Replica A, Client B on Replica B, Client C on Replica C.
  Action:
    1. Client A issues Token16.
    2. Client B and Client C both verify and cache Token16.
    3. Client A revokes Token16 on Replica A.
    4. Wait up to 1s.
  Assert:
    - Both Client B and Client C receive revocation push via their respective replica streams.
    - Both Client B and Client C local caches are evicted.
    - Subsequent verify_token on Client B and C returns VerificationResult::Invalid.

TEST: Late-Joining Replica Pub/Sub Subscription
  Setup:
    - Shared Redis at 127.0.0.1:6379.
    - Replica A running at 127.0.0.1:5111.
  Action:
    1. Client A issues Token16 on Replica A.
    2. Start Replica B at 127.0.0.1:5112 (starts after token was issued).
    3. Client B connects to Replica B and verifies Token16 -> cached in Client B.
    4. Client A revokes Token16 on Replica A.
  Assert:
    - Client B receives revocation push from Replica B.
    - Subsequent verify_token on Client B returns VerificationResult::Invalid.

TEST: Replica Send Revocation to All Connected Clients
  Setup:
    - Shared Redis at 127.0.0.1:6379.
    - Replica A running at 127.0.0.1:5111.
    - Clients A, B, and C connected to Replica A.
  Action:
    1. Client A issues Token16 on Replica A.
    2. Client B and Client C verify and cache the token.
    3. Client A revokes Token16 on Replica A.
  Assert:
    - Clients B and C receive revocation push.
    - Subsequent verify_token on Clients B and C returns VerificationResult::Invalid.

TEST: Verification with Disconnected Redis (Cached Degraded Hit)
  Setup:
    - Shared Redis running at 127.0.0.1:6379.
    - Replica A running at 127.0.0.1:5111.
    - Client A connected to Replica A.
  Action:
    1. Issue Token16 for User1.
    2. Call verify_token(Token16) -> populates local cache.
    3. Disconnect Redis server (or simulate Redis failure on Replica A).
    4. Call verify_token(Token16).
  Assert:
    - Client A returns VerificationResult::ValidDegraded(User1) directly from local cache.

TEST: Load Verification Under High Concurrency
  Setup:
    - Shared Redis at 127.0.0.1:6379.
    - Replica A running at 127.0.0.1:5111.
    - Replica B running at 127.0.0.1:5112.
    - Replica C running at 127.0.0.1:5113.
  Action:
    1. Start 100 clients for every replica (300 total).
    2. For 1 minute, run operations concurrently in random order:
      a. 20% of load: generate new token (`issue_token`).
      b. 5% of load: revoke a token (`revoke_token`).
      c. 75% of load: verify existing tokens (`verify_token`).
  Assert:
    - No unexpected unhandled exceptions or panic crashes occur.
    - Total number of creations > 1,000.
    - Total number of revocations > 100.
    - Total number of verifications > 10,000.
